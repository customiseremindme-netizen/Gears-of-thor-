# CLAUDE.md: GOT FITNEZZ website

Read this first in every session. The owner is not a developer and asks for
changes in plain language. Keep explanations short and non-technical.

## What this is

- Website for **GOT FITNEZZ — Gears Of Thor**, a gym at 30A, First Floor,
  Trichy Road, Palladam, Tamil Nadu 641664.
- A cinematic, editorial one-page site: oversized condensed type, full-bleed
  imagery, asymmetric layouts and a coordinated motion system.
- Static site built with **Astro** (no server, no database). Deploys to
  **Netlify** (chosen host) or Vercel without code changes.
- There is **no CMS or dashboard** for this site, by the owner's choice: all
  edits are made through Claude in this repository.

## Brand rules

- Logo: `src/assets/brand/logo.png` is the owner's authentic logo (keyline
  version for dark backgrounds). The original artwork is in `docs/brand/`.
  Never redraw or alter it.
- Accent colour `#D8E12A` was sampled from the lit half of the logo's shield
  (`#C4CC34` is the shaded half). It is our sampling, not a published brand
  guideline. Use the accent sparingly: one highlighted word per heading,
  primary buttons, small details.
- Colours: near-black `#0B0B0A`, warm white `#F2EFE8`, greys in
  `src/styles/tokens.css`.
- Type: League Gothic (display, uppercase) + Instrument Sans (text). Both are
  open-licence fonts installed from npm (`@fontsource`), self-hosted.

## Content rules (from the owner's brief, do not break these)

- Never invent prices, reviews, ratings, member counts, trainer details,
  qualifications, guarantees, transformation results or classes.
- Do not imply official CrossFit affiliation. Do not offer a "free trial"
  unless the owner confirms one.
- Opening hours and WhatsApp are **not confirmed**: do not show them until the
  owner confirms (`docs/OWNER-CHECKLIST.md`).
- Never present stock photos as GOT FITNEZZ's premises, staff or members.
  The gallery heading must be "MAKE TIME TO MOVE" unless the photos are the
  owner's genuine gym photos (then set `gallery.genuine: true` to use
  "STEP INSIDE GOT.").
- Never show a successful enquiry unless it was actually saved or delivered.
- Omit sections that have no real supporting information.

## Images

- All 13 photo slots currently hold **designed placeholders** (abstract light
  studies, generated by `scripts/make-placeholders.mjs`, listed in
  `src/assets/images/placeholders.json`). The owner will supply real photos
  and videos later.
- To place a photo: follow `docs/IMAGES.md` (save over the slot file, set
  `alt`, `position`, `placeholder: false`, remove from placeholders.json),
  record its source and licence in `docs/IMAGES.md`, then
  `node scripts/make-og.mjs` if the hero changed.
- Add `?slots` to any preview address to label every slot with what belongs
  there.
- Hero video: put files in `public/media/`, set `heroVideo` in
  `src/content/images.ts`. Muted, looping, no sound, paused for visitors who
  prefer reduced motion.

## Motion system (keep it coordinated)

- Hero: headline lines rise from a mask (CSS, on load), text and buttons fade
  up with a stagger, image settles from scale 1.04 to 1.
- Scroll reveals (`data-reveal` = `lines` | `up` | `fade` | `image` | `panel`)
  via `src/scripts/reveal.ts` + `.motion` CSS. Elements are hidden only once
  the script runs, so the page never loses content.
- Signature image opens from an inset frame to full width (`data-scrub="sticky"`),
  membership photo clips open with gentle parallax and the closing words drift
  (`data-scrub="pass"`), all driven by one `--p` progress value
  (`src/scripts/scrub.ts`).
- Training: sticky image + three descriptions on desktop (`training.ts`),
  simple vertical list below 1024px.
- Gallery: staggered curtain reveals, hover zoom, `<dialog>` lightbox with
  keyboard, swipe and focus return (`lightbox.ts`).
- Micro: button arrows, drawn underlines, drawn section rules, menu wipe.
- Rules: animate transform/opacity (clip-path only on a few large frames),
  small distances, one easing family (`--ease-out`, `--ease-in-out`), native
  scrolling, no loading screen, no sound, no flashing. `prefers-reduced-motion`
  turns all motion off. Phones get simpler versions (no parallax/clip effects).

## Commands

```
npm install          # once per session
npm run dev          # local preview at http://localhost:4321
npm run build        # production build into dist/
npm run check        # TypeScript / Astro checks
npm run qa           # builds must exist; screenshots + checks in qa-output/
```

`npm run qa` checks: no script errors or broken files under the production
Content Security Policy, no sideways scrolling, headings fit on screen, images
load, call/Instagram/directions links, section anchors, menu, mobile contact
bar, lightbox keyboard use, training image changes, reduced motion. Look at
the screenshots in `qa-output/` (desktop 1440, tablet 834, phone 390) before
saying a change is done.

## Hosting, previews and publishing

- Chosen host: **Netlify**, connected to this GitHub repository. Setup steps
  and costs are in `docs/HOSTING.md`. Do not create a second production site
  on another host.
- Branches: `main` is the live site. Work happens on a separate branch; each
  pushed branch gets a Netlify preview at
  `https://<branch-name-with-dashes>--<netlify-site-name>.netlify.app`
  (requires "Branch deploys: all branches" in Netlify, see HOSTING.md).
- Until `main` exists and Netlify is connected, the site lives on branch
  `claude/wonderful-tesla-t9n1fa`.

Workflow for every change request:
1. `git fetch` and start from the latest `main` (or the working branch above
   until `main` exists). Read this file.
2. Create a branch for the change. Keep unrelated features working; avoid
   rewrites for small requests.
3. Make the change; keep text in `site.ts`, design values in `tokens.css`.
4. `npm run build && npm run check && npm run qa`; review desktop and phone
   screenshots.
5. Commit and push the branch. Give the owner the preview link and a
   two-line summary. Previews are hidden from search engines automatically.
6. When the owner says "publish" / "make it live", merge into `main`.
   Netlify deploys `main` automatically.
7. Verify: the Netlify commit status on GitHub for that commit is
   successful, and the live site shows the change. Never say it is live
   based on the push alone.

## Rolling back

- Fastest: Netlify → Deploys → choose the last good deploy → **Publish
  deploy**. The live site switches instantly; `main` is unchanged, so fix
  forward or revert next.
- In Git: `git revert <commit>` on `main` and push; Netlify redeploys.
- There is no database, so rollbacks never affect data.

## Enquiry form (not connected yet)

The contact section uses direct actions (Call, Instagram, Get Directions)
because no form backend exists on the new host. Never fake a success
message. When the owner wants a form, the simplest option on Netlify is
Netlify Forms (submissions stored in Netlify, email alerts to the owner):
add the form to `Contact.astro` with `data-netlify="true"`, a honeypot,
fields Name / Mobile / Fitness goal / Preferred contact time / Message +
consent, submit with `fetch` and show success only on a 2xx response, keep
the entered details and offer retry on failure. Enable form detection in
Netlify, send a real test submission and confirm it arrives before
announcing it.

## Environment variables

Netlify provides `URL` and `CONTEXT`; Vercel provides
`VERCEL_PROJECT_PRODUCTION_URL` and `VERCEL_ENV`. No secrets exist in this
project; never commit any.
